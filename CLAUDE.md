# Enzyme Explorer — project context

A single-page mock UI for an enzyme design pipeline: browse enzymes in a table,
compare their structures in 3D, and "generate" new candidates. Built as a
claude.ai artifact; this is the local copy.

## Run it

The page **must be served over HTTP** — it uses an ES-module Web Worker and a
`.wasm` file, both of which fail under `file://`.

```bash
python3 -m http.server 8000      # then open http://localhost:8000/
```

## Files

| File | Purpose |
|---|---|
| `index.html` | The whole app — markup, CSS and JS in one file |
| `align-worker.js` | ES-module worker wrapping TM-align |
| `tmalign-wasm.js` | Emscripten glue (from npm `tmalign-wasm@0.0.6`) |
| `tmalign-wasm.wasm` | TM-align compiled to WebAssembly, 212 KB |
| `TMALIGN-LICENSE.txt` | MIT licence for the above |

`3Dmol.js` loads from a CDN (`cdn.jsdelivr.net/npm/3dmol@2.5.5`). Vendor it
locally if you need offline use.

## What is real vs. mock

**Real:** the structural alignment. `tmalign-wasm` is the original TM-align
(Zhang & Skolnick) compiled to WASM by Milot Mirdita (Steinegger lab). RMSD,
TM-score, aligned length and the rotation matrix all come from it. Verified: a
structure aligned to a copy of itself returns RMSD 0.00, TM-score 1.000 and an
identity matrix.

**Mock:** everything else. Enzyme names, kinetics, sequences and perplexities
are generated by a seeded PRNG (`mulberry32`). Structures are procedurally
built folds — a per-family backbone of helices/strands/loops, deformed by
smooth sine modes. No real PDB data is involved.

## Data model

`data[]` holds every entry; **`data[i].id === i` is an invariant** — ids index
the array directly (anchors, alignment cache keys, the scaffold picker all rely
on it). Only ever remove entries from the tail.

Each entry has a `status` forming a lifecycle:

```
generating  ->  seq  ->  folding  ->  folded
```

- `src`: `"real"` (shown as **Reference**) or `"gen"` (**Generated**)
- `ppl`: ZymCTRL-style perplexity, lower = better. `null` for Reference entries.
- `plddt`: `null` until folded.
- Helpers: `hasStruct()`, `isPending()`, `sel3D()`, `selToFold()`.

## Structural alignment

`alnRequest(anchorId, entries)` queues pairs onto a pool of up to 8 workers
(`navigator.hardwareConcurrency`). Results cache in `alnCache` keyed
`"anchorId|entryId"`.

Two deliberate choices:

1. **Only rows passing the current filters are aligned.** `alnTopUp()` runs
   from `renderBody()`, so changing a filter tops up just the newly visible
   rows.
2. **Cα-only PDBs are sent to the worker** (`pdbCaOf()`), since TM-align reads
   nothing else. ~17% faster than full backbone, identical results.

Comparison columns rank by **TM-score**, not RMSD — TM-score is
length-normalised and bounded (>0.5 ≈ same fold, <0.3 ≈ random), whereas RMSD
over a short alignment flatters shallow matches. Sort value is stored as
`1 - tm` so ascending = most similar first.

If the worker or WASM fails to load, `alnOff` flips true and the UI falls back
to index-based RMSD with a visible warning — never silently wrong numbers.

## Table

- Column order lives in `colOrder` (array of keys) — drag rows in the Columns
  dropdown to reorder. `sel` is locked to the front.
- Column widths are drag-resizable; double-click a divider resets one.
- Filters: search, EC class, structure status, Reference/Generated toggles.

## Generate / fold dialog

One dialog serves both modes via `dlgMode`:

- `"generate"` — both cards; the **Fold after generation** toggle collapses
  `#foldParams`.
- `"fold"` — sequence card hidden, used by the "Fold selected (n)" button.

Runs are async (`startRun()`), cancellable mid-flight, and can be backgrounded
by clicking outside — the Generate button then shows live progress. Cancelling
splices off placeholder rows that were never sampled, preserving the id
invariant.

## Intended real backend

The models this mocks:

- **ZymCTRL** (`AI4PD/ZymCTRL`) — a GPT-2-style *autoregressive* conditional LM
  conditioned on an EC number. **Not a diffusion model**; call `model.generate()`
  with temperature / top-k. Returns a perplexity per sequence. Seconds on a
  consumer GPU.
- **Boltz-2** (`jwohlwend/boltz`, MIT) — structure prediction via the
  `boltz predict` CLI. Minutes, GPU-bound. Use MSA-free mode for de novo
  designs; `--use_msa_server` is meaningless at ~30-40% identity to anything
  natural.

Architecture notes for wiring it up:

- The page can't call a GPU host while it is a claude.ai artifact (CSP blocks
  cross-origin fetch). Serve it from your own FastAPI process instead.
- Don't spawn a Python child process per request — weight loading dominates.
  Keep long-lived workers with models resident in VRAM, fed by a queue.
- Boltz is CLI-first, so `subprocess` fits there, but batch all sequences into
  one invocation.
- Timescales are lopsided (seconds vs. minutes), so stream sequences into the
  table first and fill structures in as they land — which is exactly what the
  mock's two-phase progress already does.
- Replacing `structOf()` with parsed Cα coordinates from real PDB/mmCIF is the
  only change the alignment path needs.

## Conventions

- No build step and no framework — plain HTML/CSS/JS, edited in place.
- Neumorphism was tried and rejected; the design is flat, with few borders.
- Test UI changes with Playwright against a local server rather than by
  inspection; several bugs here (drag targets scrolled out of a popup, a
  styled checkbox that `page.check()` can't reach) were only visible that way.
